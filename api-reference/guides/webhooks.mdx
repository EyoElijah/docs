Asynchronous events (escrow funded, payout completed, wallet credited, and similar) are delivered to the merchant `webhookUrl` as HTTP POSTs.

## Verify the signature

We sign the raw body with your `webhookSecret` (`whsec_...` from the merchant account):

```text
HMAC-SHA256(webhookSecret, "{timestamp}.{raw_body}")
```

Compare that hex digest to `x-demat-signature` using a constant-time compare. Recreate the string as `timestamp + '.' + raw_body` where `timestamp` is the `x-demat-timestamp` header (unix seconds).

## Headers

| Header | Description |
| --- | --- |
| `Content-Type` | `application/json` |
| `x-demat-signature` | HMAC hex digest |
| `x-demat-event` | Event name, for example `escrow.funded` |
| `x-demat-delivery-id` | Delivery id for retries / logging |
| `x-demat-timestamp` | Unix timestamp used in the signature |

Respond with **2xx** within a few seconds. Non-2xx responses are marked failed and retried.

## Payload

Bodies are JSON with camelCase fields:

```json
{
  "id": "evt_01hxyz",
  "type": "escrow.funded",
  "createdAt": "2026-09-18T12:00:00.000Z",
  "data": {
    "escrowId": "esc_01hxyz",
    "merchantReference": "order_12345",
    "amount": 40000,
    "currency": "NGN"
  }
}
```

Set `webhookUrl` on the merchant profile from the dashboard. Do not expose `webhookSecret` in client apps.
